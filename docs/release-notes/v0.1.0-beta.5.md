# Vigil Agent v0.1.0-beta.5

## Português

- **Conquistas do bbport ao vivo voltam a ser lidas.** Dependendo de como o launcher inicia o jogo, o
  `last_run.log` termina cada linha com `\r\r\n`; a linha `Runtime: trophy N unlocked` não era
  reconhecida e a conquista não era enviada nem anunciada. Agora as duas formas são lidas.
- **Descoberta automática do bbport portátil.** Encontra o port nos pacotes que guardam o programa na
  subpasta `bbport-windows` ou `bbport-linux` (por exemplo, descompactado em Downloads), já antes da
  primeira conquista, quando `bbport.ini` e `user` existem. A pasta `user` do port não é mais confundida
  com shadPS4. Quando o launcher usa a pasta padrão (`user_dir` vazio), a pasta do jogo configurada nele
  ainda identifica o conjunto de troféus.
- **Instalações antigas são corrigidas.** Na primeira abertura desta versão, se a detecção encontrar algo
  novo, o Vigil mostra uma vez a janela "Fontes encontradas" só com o que mudou; uma pasta do bbport que
  uma versão anterior salvou como shadPS4 aparece "no lugar de shadPS4" e é trocada se você aceitar. Pastas
  que a detecção não reconhece ficam como estão. Nada aparece quando nada mudou.
- A busca continua limitada aos lugares de sempre e a subpastas conhecidas dos pacotes: não varre o disco
  e não altera arquivos do jogo. Você confirma as pastas antes de elas serem acompanhadas.
- Atualize fechando o Vigil (menu → Sair), substituindo o executável e abrindo de novo: vínculo,
  preferências e fila são mantidos. Não há atualização automática.
- Servidor padrão: https://vigiltrophies.com. Confira os arquivos com o `SHA256SUMS.txt`. Os executáveis
  do Windows não têm assinatura de código.
- Testado com arquivos sintéticos (incluindo o formato `\r\r\n` de um log real) e a detecção num PC com o
  port v1.7.2. O envio ao vivo de uma conquista nova num jogo de verdade ainda depende do teste do dono.

## English

- **Live bbport achievements are read again.** Depending on how the launcher starts the game,
  `last_run.log` ends each line with `\r\r\n`; the `Runtime: trophy N unlocked` line was not recognized,
  so the unlock was neither sent nor announced. Both forms are read now.
- **Automatic discovery of the portable bbport.** Finds the port in packages that keep the program in a
  `bbport-windows` or `bbport-linux` subfolder (for example unpacked in Downloads), even before the first
  unlock, when `bbport.ini` and `user` exist. The port's `user` folder is no longer taken for shadPS4.
  When the launcher uses its default folder (empty `user_dir`), its configured game folder still
  identifies the trophy set.
- **Older installs are fixed.** The first time this version starts, if detection finds something new,
  Vigil shows "Sources found" once with only what changed; a bbport folder an earlier version saved as
  shadPS4 shows "instead of shadPS4" and is replaced if you accept. Folders detection does not recognize
  are left alone. Nothing is shown when nothing changed.
- Discovery stays bounded to the usual locations and known package subfolders: it does not crawl disks
  and never modifies game files. You confirm the folders before they are watched.
- To update, quit Vigil (menu → Quit), replace the executable and open it again: link, preferences and
  queue are kept. There is no automatic updater.
- Default server: https://vigiltrophies.com. Verify the files against `SHA256SUMS.txt`. Windows
  executables are not code-signed.
- Tested with synthetic files (including the `\r\r\n` format of a real log) and detection on a PC with
  port v1.7.2. Live sending of a new unlock in a real game is still pending the owner's test.

Build provenance status is reported by the release workflow below; no attestation is assumed.
